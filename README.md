# Bloomcraft

A florist assistant that recommends a bouquet from what the occasion actually is —
purpose, recipient, style, budget — and returns a costed arrangement drawn from a
structured flower database, not free text.

Alongside the web app sits a separate strand of work: **ghconfnu**, a fine-tuned
text-to-image checkpoint trained on captioned bouquet photography to generate reference
imagery for the arrangements.

![Bouquets generated by the ghconfnu checkpoint](docs/images/samples.jpg)

## Two halves

The repository contains the web application. The image model is trained and run outside
it — see [The ghconfnu checkpoint](#the-ghconfnu-checkpoint) for why it is not committed
here.

| | What it does | Where it lives |
| --- | --- | --- |
| Web app | Bouquet recommendation, flower library, image recognition, accounts, billing | this repo |
| ghconfnu | Fine-tuned diffusion checkpoint for bouquet imagery | `Assets/` (untracked) |

## The web app

### Bouquet recommendation

`MultiStepBouquetGenerator.tsx` walks the user through four steps — primary purpose, a
secondary choice that branches on it (which occasion / which recipient), then style and
budget, then free-text notes. The branching matters: "gift" and "special occasion" need
different second questions, and asking one generic question instead produces vaguer input.

The completed brief is turned into a prompt and sent to the Express proxy, which calls
DeepSeek via OpenRouter. The model is constrained to emit a JSON object with a fixed
shape — flowers with quantities, total price, style, occasion, description — so the
response can be rendered as a costed arrangement rather than a paragraph.

LLMs habitually wrap JSON in markdown fences, so `safeJsonParse()` in `server/index.ts`
strips them before parsing and returns `null` rather than throwing on malformed output.
The route then answers with a usable error instead of a stack trace.

### Flower library

`src/data/flowers.ts` defines the `Flower` shape — scientific name, colours, meaning,
occasions, seasons, price range, care instructions, symbolism, growing regions. This is
what makes the recommendations concrete: the model picks from a known catalogue with real
prices attached, so the total is arithmetic rather than a guess.

### Image recognition

`FlowerRecognition.tsx` runs `google/vit-base-patch16-224` **in the browser** through
`@huggingface/transformers` with the WebGPU backend. Nothing is uploaded — the image is
drawn to a canvas and classified locally. The top five labels are then fuzzy-matched
against the flower database in both directions (label contains name, name contains label)
so a hit like "daisy" resolves to the catalogue entry.

### Accounts, credits, billing

Supabase handles auth and Postgres. Generation costs a credit, deducted through a
`deduct_credits` RPC so the decrement is atomic server-side rather than a
read-modify-write from the client. Subscribers bypass the credit check entirely.

Stripe runs through four Supabase edge functions — `create-checkout`, `check-subscription`,
`customer-portal`, `delete-account`. Row-level security is enabled on every table, with
policies in `supabase/migrations/`.

## The ghconfnu checkpoint

A Stable Diffusion checkpoint fine-tuned on hand-captioned bouquet photography, producing
the reference imagery above.

Training data went through four iterations, each a directory of paired `image.jpg` /
`image.txt` files:

| Dataset | Pairs | Notes |
| --- | --- | --- |
| `ghconfnu_v1_training_data` | 35 | first pass |
| `ghconfnu_v2_training_data` | 20 | |
| `ghconfnu_v3_training_data` | 20 | longer, more structured captions |
| `ghconfnu_v3.5_training_data` | 10 | refinement pass |

The captions got substantially more specific across versions. v1 reads like a label:

> An image showing a classic and passionate bouquet made with red roses and white baby's
> breath, wrapped in white paper, with a timeless and romantic style.

v3 separates subject, wrapping, filler, foliage and lighting into distinct clauses, so
each is a handle the prompt can pull on independently at inference:

> A photorealistic image, showing a stunning, elegant bouquet, fully wrapped in a big
> matte dark gray paper. The bouquet is made of rich, velvety red roses in full bloom,
> surrounded by clouds of tiny white baby's breath flowers and soft, round eucalyptus
> greenery as accent foliage. The soft, diffused outdoor sunlight illuminates the bouquet
> […] without any harsh shadows.

Sampling settings and the negative prompt that produced the images above are recorded in
`Assets/ghconfnu_v1_results/Pink_bouquet_prompt.txt` — CFG 3, 59 steps, with a negative
prompt that mostly exists to keep people, vases and watermarks out of frame.

`Assets/` is **not tracked in git**: the checkpoint alone is 2.6 GB, past GitHub's file
limit. The samples in `docs/images/` are downscaled copies of `ghconfnu_v1_results/`.

## Stack

| Layer | Choice |
| --- | --- |
| Frontend | React 18, TypeScript, Vite, Tailwind, shadcn/ui, React Router, TanStack Query |
| Backend-as-a-service | Supabase — Postgres, auth, RLS, edge functions |
| Proxy | Express (TypeScript), keeps the OpenRouter key server-side |
| Text model | DeepSeek Chat v3 via OpenRouter |
| Vision model | ViT base patch16-224, in-browser via transformers.js + WebGPU |
| Payments | Stripe |
| Image model | Fine-tuned Stable Diffusion checkpoint (ghconfnu) |

The app was scaffolded with [Lovable](https://lovable.dev); the DeepSeek integration,
prompt design and image-model work were done by hand.

## Running locally

Requires Node.js and a Supabase project.

```bash
npm install
npm run dev            # Vite dev server
```

The recommendation endpoint needs the proxy running alongside it:

```bash
cd server
npm install
echo "OPENROUTER_API_KEY=sk-or-..." > .env
npm run dev            # listens on :3001
```

Supabase credentials are read from `src/integrations/supabase/client.ts`. Apply the
schema with the migrations in `supabase/migrations/`.

The Express server refuses to start a request without `OPENROUTER_API_KEY` and returns an
explicit "backend misconfigured" error rather than failing opaquely at the API call.

## Known gaps

- `(Unused)BouquetGenerator.tsx` is the superseded single-step generator, kept for
  reference.
- The ghconfnu checkpoint is not wired into the app — generated imagery is produced
  offline and used as reference, not served per request.
- Recognition accuracy is limited by ViT's ImageNet label set, which is coarse for
  flowers; the fuzzy match to the catalogue papers over this rather than solving it.
